# M1 实现计划 · 《掠影》第一幕可玩切片

## 1. 交付形态
- 开发：`index.html` + `src/**/*.js`（ES Modules，importmap 指向锁定版本 three@0.160.0）。
- 发布：`npm run build` 用 esbuild 把 `src/` 打成一个内联模块，输出单文件 `dist/index.html`；Three.js 与后期模块从 jsDelivr 加载同一版本。
- 测试：`npm test` 用 `node:test` 跑 `tests/*.test.mjs`；`npm run smoke` 用无头 Chromium 打开整页，检查控制台并截图。

## 3. 坐标与地图
- 单位米，Y 向上；+Z 为南（雨林），−Z 为北（城市）。地图 x、z ∈ [−1000, 1000]。
- 水面 y = 0。淹水林 z > 450；雨林带 −140 < z < 450；清障带 −200 < z < −140；研究所 −500 < z < −200，x ∈ [−220, 220]；城市 z < −540。
- 小溪从淹水林蜿蜒向北，在 x≈40 处进入排水涵洞，从清障带下方穿过围栏，进入院内的混凝土排水渠。

## 4. 关键设计判断（总监决定，支柱范围内）

### 提案：雷达的可读性
目标：支柱 1「低即是隐，低即是险」，边缘感。
- 方案 A：只做视线 + 地形遮蔽。亮点是规则简单；代价是院内开阔地雷达几乎全视，进院就等于暴露。
- 方案 B：视线 + 遮蔽 + 多普勒门限（径向速度 < 6 m/s 视为地杂波）+ 塔下 40 m 盲区。亮点是真实周界雷达的工作方式，给出“院内要慢、林中可以快”的节奏语言；代价是多一条要教给玩家的规则。
- 推荐：B。HUD 雷达读数直接显示门限，调试层画出扫描扇区和速度判定。

### 提案：被发现前的半秒
目标：边缘感。
- 每个观察者独立怀疑度，单帧上涨速率封顶 100/0.6 s；屏幕边缘弧形标记 + 来自敌人方向的升调提示音；超过 30 时敌人停步转头并低声通报。
- 结算回放记录每一次状态跃迁：谁、因为哪条线索（视线/探照灯/雷达/电磁/痕迹类型/摄像头/手机/热成像/卫星）、在哪里。

### 提案：指令系统
目标：默契感。
- 潜行期四条指令：跟随航迹、原地待命、惊扰诱敌、扫描标记；开战后同一组按键切换为：集火、包抄、掩护、归队。磐石的干扰场作为专属指令（T）。
- 航迹复刻采用精确回放（回声 2 s、微光 3.5 s、磐石 5 s 延迟错开），保证“你安全走过的路，它也安全”在空间上成立。

### 提案：撤离的隐形倒计时
目标：心跳。
- 取走场核后，机库巡逻守卫每约 90 秒巡视一次空台；被发现空台会让营地进入搜索。微光会在无线电里提醒节奏。

## 5. 曝光模型
- 影像证据按“通道”区分：研究所人员与摄像头的影像走卫星终端（警报后上传 40 s，磐石干扰 +15 s）；城市路人走蜂窝网络（30 s，磐石干扰场内暂停）。
- 场脉冲瘫痪终端 → 本次上传中断，终端 20 s 后重启并从零开始；摧毁终端或发电机房 → 永久离线。
- 黑箱 = 终端离线 + 磐石干扰场展开。黑箱内开战不产生曝光。

## 6. 逐波升级（警报后）
步兵 → 无人机群（雨中无法起飞，改为提前出车） → 两辆装甲巡逻车 → 武装直升机（三阶段：机炮扫射 → 火箭齐射 + 投放无人机 → 低空探照灯死斗）。

## 7. 验证策略
- 能自动测的：单元测试（悬浮弹簧收敛、跃升时长与冷却、静默下沉速率与 0.8 s 升压、热量与过热、怀疑度 0.6 s 下限、树冠/河岸遮挡雷达、卫星判定、状态机跃迁、上传 40 s 与脉冲切断、评级规则、航迹延迟、诱敌改变守卫路线、雨中无人机不起飞、全部武器效果与代价）。
- 需要人判断的：速度感、默契感、战斗爽，写「需要主人试玩」。
