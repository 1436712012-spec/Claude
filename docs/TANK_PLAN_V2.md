# 《霓虹重装 NEON IRONCLAD》作品计划书 V2

> 类型：2D 横版坦克射击（卷轴动作射击）｜平台：浏览器（WebGL2，单个 HTML，零运行时依赖）
> 核心诉求：**战斗爽** + **精美绝伦的画面与特效炫技**
> 状态：规划阶段。以下均为设计构想，尚未实现、尚未验证。
> 取代：`docs/GAME_PLAN.md`（《守夜炮》防空构思，已作废）。名字可改。

---

## 1. 一句话

**一辆会"唱歌"的重装坦克，在霓虹黄昏的废土上一路推平。** 每一发炮弹都有重量，每一次爆炸都是一场小型视觉秀，一波连杀会让整个屏幕一起震动、发光、变形。

## 2. 设计支柱

| 支柱 | 含义 | 判据（可测试） |
|---|---|---|
| ① 重量感 | 开炮要有后坐、命中要有顿帧 | 主炮命中同时触发：顿帧、震屏、冲击波、碎片、闪光、音效 6 项反馈 |
| ② 连杀快感 | 越打越爽，节奏有起伏 | 有连击计量、过载（Overdrive）大招、多杀慢动作 |
| ③ 屏幕即奇观 | 画面本身就是奖励 | 任意一帧截图都能直接当壁纸；同屏 ≥ 5 万粒子仍稳定 60 fps |
| ④ 可读性优先 | 特效华丽但不糊 | 敌方弹幕、可伤害区域始终高对比；有"特效强度"滑块 |

> 取舍：特效炫技最大的敌人是"看不清"。所以做了 ④，所有炫技都受它约束。

## 3. 战斗设计

### 3.1 坦克与操作

| 部件 | 说明 |
|---|---|
| 车体 | 左右行驶、爬坡（按地形法线倾斜）、跳跃喷口（短时悬浮）、冲刺撞击 |
| **主炮** | 鼠标 360° 瞄准，按住充能，释放时有三档威力：轻 / 重 / 满蓄（贯穿 + 冲击波） |
| **副武器（同轴机枪）** | 连射，有过热条，过热时枪管发红并喷蒸汽 |
| **肩射导弹** | 锁定 3 个目标后齐射，带尾焰与烟迹 |
| **过载 Overdrive** | 连击槽满后触发 6 秒：时间减缓、炮弹变等离子束、屏幕边缘色彩分离 |
| **装甲反应** | 被击中时爆出反应装甲碎片，吸收一次伤害，冷却后恢复 |

键盘：A/D 行驶，Space 喷口，Shift 冲刺；鼠标瞄准，左键主炮，右键机枪，Q 导弹，E 过载。预留手柄与触屏。

### 3.2 爽感"手感栈"（Juice Stack）

每次命中按下表**叠加**，这是实现的验收清单：

| 层 | 实现 |
|---|---|
| 顿帧 | 轻 2f / 重 5f / 击杀 3f / Boss 部件 8f，仅暂停敌人和特效，不暂停玩家输入 |
| 震屏 | "创伤值"模型：`shake = trauma²`，用噪声驱动位移与旋转，不同武器注入不同创伤 |
| 后坐力 | 车体向后位移 + 炮管回缩曲线（弹簧阻尼），履带扬尘 |
| 炮口 | 三层闪光（核心白、橙色冲击、烟环）+ 抛壳 + 暖色动态光源 0.1 秒 |
| 命中 | 冲击波环（屏幕空间折射）、火花、碎片、受击闪白、数字弹出（可关） |
| 击杀 | 敌人按材质碎裂（金属碎片 / 火球 / 电弧），残骸带物理继续飞行 |
| 多杀 | 2 秒内 ≥ 3 次击杀触发 0.4 秒慢动作，镜头轻微推进，FOV 脉冲 |
| 音频 | 低频冲击 + 中频撕裂 + 高频闪烁三层合成，音高随连击微升 |
| 色彩 | 击杀瞬间全屏对比度提升 + 辉光脉冲 |

### 3.3 敌人

| 敌人 | 行为 | 玩家应对 |
|---|---|---|
| 步兵 / 炮塔 | 基础压力，成群出现 | 机枪扫射，满足连杀 |
| 装甲车 | 冲撞，前装甲硬 | 蓄力主炮、打侧后 |
| 迫击炮 | 抛物线落点预警圈 | 走位 |
| 无人机群 | 编队、环绕、自爆 | 导弹锁定 |
| 直升机 | 空中扫射 | 主炮仰角、跳跃 |
| 盾兵 | 正面盾，盾可被击破 | 满蓄贯穿 |
| 电磁塔 | 范围电弧，周期开关 | 抓空档 |
| **Boss ×5** | 多部件、多阶段，部件被毁后行为改变 | 每个都有"表演性"的击破演出 |

### 3.4 关卡节奏

5 个关卡，每关 8–12 分钟：**推进 → 小高潮 → 休整补给 → 大场面 → Boss**。每关一个标志性场景（见第 5 节）。关卡由手工编排的"事件脚本 + 动态补刷"组成，避免匀速刷怪。

### 3.5 成长

- 战利品掉落"改装模块"（炮管、装甲、引擎、过载芯片），每关结束三选一。
- 模块有视觉反馈：换炮管会改变炮的外观和炮口特效，**成长看得见**。
- 示例：磁轨炮管（贯穿 + 电弧）、燃烧弹（地面火墙）、连锁闪电、重力弹（把敌人吸成一团再引爆）。

## 4. 画面与特效（本作的重点）

### 4.1 美术方向：霓虹黄昏废土

**为什么选这个**：剪影 + 轮廓光 + 强色彩对比，是"代码生成美术"也能显得精美的风格，并且天然适合辉光、爆炸和光照。

- 色彩：紫橙渐变天空、青粉霓虹、深色剪影地形，爆炸用高亮暖色形成视觉焦点。
- 层次：6–8 层视差（远山、城市天际线、烟尘、前景杂物），每层带大气透视与雾。
- 角色：用**矢量 / SDF 分层绘制** + 程序化材质（金属划痕、锈、反光），再生成法线贴图，参与实时光照。不依赖外部图片。

### 4.2 渲染管线（WebGL2，HDR）

```
① 场景绘制到 RGBA16F 帧缓冲（HDR）
   - 批处理精灵（带法线）、地形、实例化粒子
② 2D 动态光照：法线 + 多光源（炮口、爆炸、霓虹灯、曳光弹），带投影阴影（可选）
③ 屏幕空间效果
   - 冲击波折射（扭曲贴图）、热浪、水面反射
   - 体积光（径向模糊 god rays）、雾
④ Bloom：双 Kawase 模糊链，多级阈值
⑤ 色调映射（ACES 近似）+ 色彩分级（LUT 程序生成）
⑥ 后期：色差（受击时增强）、暗角、颗粒、FXAA / 细微锐化
⑦ UI 叠加（原生分辨率，不受后期影响）
```

| 编号 | 特效 | 技术 | 难度 | 降级方案 |

### 4.4 性能预算与画质档位

| 项目 | 预算 |
|---|---|
| 帧率 | 1080p 目标 60 fps；中端笔记本集成显卡不低于 45 fps |
| 粒子 | 高档 5 万，中档 2 万，低档 5 千 |
| 后期 | 总 GPU 耗时 ≤ 4 ms |
| 自适应 | 运行时监测帧时间，自动调节粒子上限与后期分辨率 |
| 设置 | 画质档位、特效强度、屏幕震动、闪光、辉光强度，均可调 |

### 4.5 光敏与可读性

- 全屏闪光亮度变化不超过每秒 3 次；提供"减少闪光 / 震动"总开关。
- 敌方子弹始终使用高对比色并带轮廓，避免被特效淹没；强特效期间弱化背景辉光。

## 6. 技术方案

### 6.1 选型

- **WebGL2 + 原生 ES Modules，零运行时依赖。** 游戏逻辑自写，渲染自写批处理。
- 构建脚本把所有模块内联成单个 `dist/neon-ironclad.html`。
- 音频全部 WebAudio 程序化合成：炮声（低频冲击 + 噪声撕裂）、爆炸、引擎（随转速变化）、导弹呼啸、合成器配乐（随战斗强度分层加入）。

### 6.2 目录规划

```
tank/
  index.html
  src/
    main.js
    core/     loop(固定步长+插值) · input · rng · pool · math · time(时间缩放、顿帧)
    gfx/      gl · batch(精灵批处理) · particles(GPU) · lighting · post(辉光/色调/折射)
              fluid · terrain-render · shaders/ · palette · sdf-art(矢量/SDF 绘制)
    sim/      tank · weapons · projectiles · enemies/ · boss/ · terrain(位掩码+破坏)
              debris(碎片/残骸) · combo · overdrive · director(关卡脚本) · upgrades
    audio/    engine · synth · music · sfx
    ui/       hud · menus · upgrade-pick · settings
    data/     enemies · weapons · stages · modules
  tools/      build.mjs · screenshot.mjs
  tests/
```

### 6.3 关键算法

- **固定步长 60 Hz** + 渲染插值；时间缩放用于顿帧、慢动作与过载。
- **地形**：位掩码（每像素是否实心）+ Marching Squares 提取轮廓用于碰撞与渲染；爆炸用圆形布尔挖坑；用法线估计让坦克贴地倾斜。
- **弹道**：半隐式欧拉积分，主炮带少量重力，曳光弹用拖尾线。
- **震屏**：`trauma` 衰减 + 噪声驱动，位移与旋转分别缩放。
- **GPU 粒子**：粒子状态存纹理，每帧在 GPU 上更新位置与寿命，实例化渲染；新粒子通过发射缓冲注入。
- **光照**：每个光源是一个带半径和颜色的点，法线 · 光向 · 衰减累加；炮口和爆炸光源有短寿命。
- **自适应画质**：滑动窗口帧时间，超限则逐级关闭 V2、V9、降低粒子上限。

## 8. 测试与质量

- **性能**：自动化跑固定场景，记录帧时间与粒子数；每个里程碑设预算。
- **截图回归**：Playwright 无头渲染固定种子的固定帧，与基准做像素差，覆盖后期管线。
- **确定性**：固定种子下模拟结果可复现，便于调试。
- **手感检查表**：手感栈 9 层逐项勾选，每次改动回归。
- **无障碍**：减少闪光 / 震动、辉光强度、色盲友好的弹幕配色。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 美术天花板：代码生成的画面不够"精美" | 选霓虹剪影风格；先做 M2 看效果再决定投入；必要时引入手工像素/矢量资源，请主人确认 |
| 特效太多导致看不清 | 支柱④；弹幕高对比；特效强度滑块 |
| GPU 粒子与流体兼容性 | 全部有降级方案；先检测 WebGL2 与浮点纹理扩展 |
| 性能波动 | 自适应画质；每个里程碑设预算 |
| 范围过大 | P0/P1/P2 分级；先做手感实验室 |
