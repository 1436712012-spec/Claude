# 《缓冲 BUFFERING》作品计划书

> 副标题：一盘永远加载不完的录像带
> 一句话：**你没有掉进后室，你只是点了下一个视频。**
> 类型：2D 侧视 · 程序生成银河城 · 规则怪谈式动作冒险
> 平台：浏览器（Canvas 2D + WebGL2 后处理，单个 HTML 文件，零运行时依赖）
> 状态：规划阶段。本文所有机制均为**设计构想，尚未实现、尚未验证**。

## 1. 一页纸概念

**核心幻想**：一个被推荐算法推进后室的观众，学会像剪辑师一样操纵现实：暂停、倒带、快进。你要在无尽的自动播放里活下去，并拼出"谁在看"的答案。

**为什么是"录像带 / 播放器"**：这个隐喻同时解决了五件事：

1. **美学**：VHS 噪点本身就是梦核和怪核的标配。
2. **机制**：暂停、倒带、快进是三个自带直觉的能力，也是银河城的钥匙。
3. **界面**：整个 HUD 做成视频播放器，进度条就是地图。
4. **叙事**：弹幕和评论区是天然的碎片化叙事载体。
5. **无结局**：视频播放完会自动播放下一个。

**体验目标情绪**：不安 > 好奇 > 掌控感 > 释然。不追求"吓一跳"。

### 四根设计支柱

| 支柱 | 含义 | 落地 |
|---|---|---|
| ① 错位胜过惊吓 | 恐惧来自"哪里不对"，而不是"它突然冲出来" | 无惊吓宪章、理智感知层 |
| ② 世界是可操作的录像带 | 玩家用遥控器编辑现实 | 暂停 / 倒带 / 快进、播放器 UI |
| ③ 规则即怪物 | 怪物是一组可被发现、验证、利用的规则 | 规则怪谈式战斗，笔记可能是假的 |
| ④ 每盘都不同，每盘都可解 | 程序生成，但有证明 | 求解器、视频号种子、Bot 验证 |

## 2. 无惊吓宪章（硬性设计守则）

对应 Q9a。每条都可以在测试里检查。

1. **无即时死亡**：任何单次伤害不超过满血的 35%。
2. **预警原则**：实体出现前至少有 3 秒的音频或视觉预兆；任何实体不得在玩家视野或听觉范围内凭空生成。
3. **前摇下限**：普通攻击前摇 ≥ 12 帧（200 ms），重攻击 ≥ 24 帧。
4. **响度安全**：主总线后接压缩器 + 限幅器；任何单个音效比环境底噪高出不得超过 +9 dB；提供"降低突发声响"选项。
5. **闪烁安全**：全屏亮度变化不得超过每秒 3 次；故障特效不得出现大面积红色闪烁。提供"减少闪烁 / 震动 / 故障"总开关，开启后特效降级为静态淡入淡出。
6. **公平原则**：理智低时 HUD 可以"说谎"，但每个谎言必须能在 5 秒内通过另一条信息渠道（声音、画面、位置）交叉验证。
7. **规则可发现**：每条实体规则至少有 3 条独立线索（见第 12 节"三线索原则"）。

## 3. 世界结构

### 3.1 世界是一张"播放列表"

一盘录像带（一个视频号种子）生成 **6 个层级**。层级之间由**接缝**连接。接缝是画面里"压缩失败"的位置，走进去就是一次 noclip：画面像拖动进度条一样跳切。

```
      [L0 黄色单调]──接缝──[L1 宜居地带 ◆枢纽]──接缝──[L2 管道梦境]
            │                       │                        │
          接缝                    接缝                     接缝
            │                       │                        │
      [LX 标注层]──────────[L37 池厅]──────────────[LΩ 播放队列]
```

- 接缝**默认单向**（只能"掉进去"）。获得**稳定器**之后才能双向穿行，这是银河城的主钥匙之一。
- 图的拓扑每盘不同：L1 永远是枢纽，LΩ 永远在离出生点最远处，其余按种子洗牌，并保证至少有两个环路用于产生捷径。
- 世界图在开局时就完整生成，各层的内部地图按需在 Worker 里生成。

### 3.2 六个层级总览

| 层级 | 来源 | 主美学 | 生成算法 | 签名机制 | 主要威胁 | 给予的能力 | 目标时长 |
|---|---|---|---|---|---|---|---|
| **L0 黄色单调** | 后室 Level 0 | 梦核（偏冷） | 漂移式 WFC | 教学：移动、战斗、理智；"语义漂移" | 微笑者、雕塑（Boss） | 取景器 | 12 min |
| **L1 宜居地带** | 后室 Level 1 | 梦核（安心的怀旧） | 营地模板拼装 + 程序化居民 | 交易、贩卖机、工坊、背叛事件 | 低 | 暂停 | 枢纽，累计约 15 min |
| **L2 管道梦境** | 后室 Level 2 | 怪核（工业） | 管网流量图 + 阀门谜题 | 蒸汽、阀门、穿墙追逐 | 老人（Boss）、管道猎犬 | 倒带 | 18 min |
| **L37 池厅** | 后室 Level 37 | 池核 | 房间网格 + 水位场 + 拱门 | 游泳、水位谜题、焦散、回声定位 | 救生员（Boss）、池底阴影 | 快进 + 潜水镜 | 18 min |
| **LX 标注层** | 原创 | 怪核 | 力导向布局 + 标注语法 | 标注即机制：箭头是传送带，圆圈是触发区 | 弹窗体（Boss）、标注者 | 稳定器 | 15 min |
| **LΩ 播放队列** | 原创 | 梦核（童年之家） | 非欧房间图 | 循环走廊规则、进度条 Boss、自动播放 | 重播、进度条（最终） | — | 12 min |

合计约 90 分钟（含枢纽往返与尸体回收），落在 Q20 的 1–2 小时区间内。

## 4. 核心玩法循环

| 时间尺度 | 循环 |
|---|---|
| **30 秒** | 观察 → 判断实体规则 → 试探 → 战斗或绕行 |
| **5 分钟** | 探索房间 → 读取碎片 → 验证规则 → 取得收容品或杏仁水 |
| **30 分钟** | 解开一道能力门 → 回溯旧区域 → 发现新接缝 |
| **一盘（~90 分钟）** | 走完 6 层 → 获得全部能力 → 在 LΩ 面对进度条 → 自动播放，下一盘开始 |

**一次典型的 30 秒**：走廊尽头有一个只在黑暗里移动的东西 → 你用取景器观察它 → 它在镜头里不会动，肉眼看却在靠近 → 笔记里说"怕光"，但你试了荧光棒，它纹丝不动 → 说明笔记有误，是"被取景器注视时静止"，于是你转身打它。

## 5. 移动与空间语法

**为什么用"剖面房间"**：后室本质是 3D 走廊迷宫。侧视 2D 里最忠实的转译，是"玩偶屋式剖面"：横向房间、多层楼板、墙上的门。门通往相邻房间。

- **内部分辨率**：384 × 216，整数倍放大。瓦片 16 × 16。
- **房间**：宽 1–4 屏，高 1–2 屏，镜头在房间内滚动，带视差层。
- **门**：房间之间用"剪辑"式转场（磁带拼接，0.25 秒），不用淡入淡出。
- **背景门**：画在后景层的门，按 ↑ 进入，用于产生"从房间里走进更深的房间"的感觉。
- **手感参数（初值，M1 调优）**：

| 参数 | 值 |
|---|---|
| 跑速 | 72 px/s |
| 跳跃高度 | 约 2.5 瓦片（40 px） |
| 土狼时间 / 跳跃缓冲 | 6 帧 / 6 帧 |
| 翻滚 | 18 帧，无敌 4–13 帧，距离 56 px |
| 游泳 | 浮力 + 阻尼，下潜时有气息条 20 秒（潜水镜 45 秒） |

## 6. 战斗系统：规则怪谈式战斗

### 6.1 为什么这样设计

主人要"完整战斗系统"，又要"无惊吓"。我的判断：做成**可读、可学、可反击**的战斗，每只怪物是一套"规则"。你打得赢它，是因为发现了规则；打不赢时，也可以靠血量硬扛，但代价更大。这样战斗既完整，又保持了推理的味道。

### 6.2 玩家动作

| 动作 | 起手 | 判定 | 收招 | 耐力 | 备注 |
|---|---|---|---|---|---|
| 轻击（3 连） | 8f | 4f | 10f | 12 | 取消窗口在判定后 |
| 重击 | 22f | 6f | 20f | 28 | 伤害 ×2.2，削韧 ×2.5 |
| 翻滚 | — | 无敌 4–13f | 5f | 20 | |
| 格挡 | 即时 | 持续 | 6f | 受伤 ×0.8 | 减伤 70% |
| **完美暂停**（格挡起始 8f 内） | — | — | — | 0 | 完全免伤，敌人硬直 0.8 s，顿帧 6f，+1 磁带段 |
| 投掷（荧光棒、闪光灯、噪音罐） | 14f | — | 8f | 8 | 用于测试规则 |
| 钉枪 / 信号枪 | 12f | — | 18f | 10 | 弹药有限 |

- 生命 100，耐力 100（静止 0.6 秒后每秒回复 30）。
- 伤害类型：**物理 / 光 / 声 / 水 / 记忆**。记忆伤害打的是理智，不是生命。
- 近战武器按"拾荒"风格：钢管、消防斧、拖把、球棒；各自有重量、速度、削韧参数。
- **播放速度难度**：0.75× / 1× / 1.25×，是整个模拟的时间缩放。这既是难度选项，也契合播放器隐喻。

### 6.3 规则语法（核心炫技点）

每个实体 = 属性 + AI 行为树 + **一组规则**。规则是数据，用小语言描述：

```
WHEN <条件> THEN <效果>

条件：observed(取景器|肉眼) · lit / dark · noise > θ · wet · sanity < θ
      carrying(物品) · paused · distance < d · facing(away|toward)
效果：freeze · flee · enrage · phase(穿墙) · drain(sanity, r) · slow · summon · reveal
```

**每盘变异机制**：

1. 每个物种有一个**规则池**，每盘随机抽 2–3 条生效，外加 1 条**不生效的诱饵规则**写进笔记。
2. 笔记来源有三类：真实记录、过时记录、**伪造**（NPC 说谎、理智低时的误读）。
3. 玩家通过实验验证规则，验证后在线索墙里标为"已证实"。
4. 因此上一盘的知识只能部分延续，仍需现场验证。

### 6.4 实体卡片样例

**雕塑（173 式，L0 Boss）**
- 属性：生命 220，韧性高，移动只在"未被观察"时发生。
- 池：`WHEN observed(肉眼) THEN freeze`、`WHEN observed(取景器) THEN freeze`、`WHEN dark THEN speed×1.6`、`WHEN noise>θ THEN turn_toward`
- 本盘生效（示例）：取景器 + 黑暗；诱饵："怕噪音"。
- 阶段：画廊里同时有多尊，需要用光与取景器互相掩护。
- 硬扛路线：能打，但黑暗里它加速，耐力消耗会让你输。

**老人（106 式，L2 Boss 追逐）**
- 属性：穿墙，经过之处留下"腐蚀"贴图，减速。
- 池：`WHEN steam THEN flee`、`WHEN paused AND decal THEN freeze`、`WHEN lit THEN slow`
- 流程：追逐 → 引到蒸汽阀门区 → 触发陷阱；或者直接打，但伤害高、血量厚。

**救生员（原创，L37 Boss）**
- 池：`WHEN whistle THEN stagger`（声伤害）、`WHEN wet AND noise THEN enrage`、`WHEN drained THEN lose_water_buff`
- 流程：与水位谜题联动，排干池水后它失去水中增益。

**弹窗体（1471 式，LX Boss）**
- 本体是对 HUD 的入侵：屏幕上出现弹窗，玩家需要在倒计时内"关闭"，否则理智持续下降。
- 战斗阶段：关闭弹窗会短暂暴露它的真身，此时可以攻击。

**进度条（LΩ 最终 Boss）**
- 不可杀死。它会把你"拖动"回之前的房间。
- 解法是找到并按下"下一个"，也就是触发自动播放（第 12 节）。

### 6.5 战斗质量约束

- 所有攻击前摇 ≥ 宪章下限；所有判定区在前摇期间有可见预警。
- 敌人不允许"不可闪避的攻击"。若有地面扫荡，必须存在翻滚或跳跃窗口。
- 韧性系统：连续受击累积韧性伤害，超过阈值硬直。Boss 有二阶段，阶段切换给玩家 2 秒缓冲。

## 7. 理智系统与杏仁水

### 7.1 理智值（0–100）

| 区间 | 状态 | 感知层变化 |
|---|---|---|
| ≥ 75 | 清醒 | 无 |
| 50–74 | 不安 | 轻微色溢、背景音轻度走音 |
| 25–49 | 失真 | 画面扭曲、幻觉实体偶发（无碰撞）、HUD 数值偶发错误、笔记出现误读 |
| < 25 | 游离 | 严重双影、地图标记漂移、幻觉门、字幕乱码、音频反相片段 |
| 0 | 信号丢失 | 强制 noclip 到随机层级，且**没有尸体**；之后 2 分钟地图记忆被打乱 |

- 下降来源：黑暗（−0.5/s）、被某些实体观察、读阴暗档案、反复经过"漂移"区域。
- 回复来源：杏仁水、安全点休息、受信任 NPC 的陪伴（+0.2/s）、解读完整线索（一次性奖励）。

### 7.2 杏仁水

- 回复 +25 理智、+10 生命（5 秒内），饮用耗时 1.2 秒且可被打断。
- 90 秒内连饮，第二瓶效果减半。
- 携带上限 3（保温瓶升级后 5）。
- 来源：L1 的贩卖机（SCP-294 式"可以倒出任意液体"）、探索拾取、NPC 交易。

### 7.3 感知层（炫技点 S5）

模拟层持有**真实状态**，渲染层通过 `perceive(entity, sanity)` 决定画什么：

- 幻觉实体：只存在于感知层，无碰撞。
- HUD 说谎：数值、地图标记、门标签偶尔出错。
- 文字腐蚀：怪核层的文字会随理智下降发生字符替换。
- 受公平原则约束（宪章第 6 条）：每个谎言都有 5 秒内的交叉验证渠道。

## 8. 收容品与遥控器

### 8.1 遥控器能力（银河城的钥匙）

| 能力 | 来源层 | 效果 | 代价 | 门控示例 |
|---|---|---|---|---|
| **取景器** | L0 | 按住进入取景视图，揭示"只存在于录像里"的隐藏物、门、规则线索 | 长时间使用降低理智 | 隐藏门、取景器规则 |
| **暂停** | L1 | 3 秒内冻结半径 96 px 内除你以外的一切 | 1 磁带段，理智 −3 | 定时门、压碎机、蒸汽 |
| **倒带** | L2 | 把最近 ≤ 4 秒的世界状态（含你的位置与生命）回滚 | 2 磁带段，理智 −6 | 断桥、坠落、被打碎的物体 |
| **快进** | L37 | 对自己：1.2 秒冲刺 ×2.2；对物体：把它"老化"30 秒 | 1 磁带段 | 生锈栅栏、蒸发的水、生长的植物 |
| **潜水镜** | L37 | 水下气息 20 → 45 秒，并看清水下 | 无 | 深水区 |
| **稳定器** | LX | 穿过薄墙；接缝可双向通行 | 持续消耗理智 | 薄墙、返回旧层 |

- **磁带段**：上限 3，空闲时每 20 秒回复 1 段，完美暂停额外 +1 段。
- 倒带**不回滚**：理智、磁带段消耗、物品消耗。这样不能被无限滥用。

### 8.2 其他收容品

- 采用 SCP 风格的收容等级 **Safe / Euclid / Keter**，等级越高能力越强、副作用越大。
- 样例：宝丽来相机（拍下实体使其短暂"归档"静止，Euclid，每张底片消耗）、SCP-914 式工坊（把收容品投入"精加工"升级，也可能毁掉它）、SCP-500 式药丸（一次性全回复，Keter 副作用：永久降低理智上限 5）。
- 目标数量：约 30 件。

## 9. 程序生成管线

### 9.1 总览

```
种子（视频号）
  └→ ① 世界图（6 节点 + 接缝，钥匙 / 锁分配）
       └→ ② 层级布局（每层专用生成器）
            └→ ③ 房间装饰（陈设语法，泊松盘采样）
                 └→ ④ 实体与规则分配（危险曲线）
                      └→ ⑤ 物品与碎片放置（三线索原则）
                           └→ ⑥ 验证（求解器 + 软锁检查 + 时长估计）
                                └→ ⑦ 输出紧凑 LevelData（类型化数组）
```

### 9.2 关键设计

**种子 = 视频号**：用类似视频站 ID 的 11 位 base58 字符串（例如 `4xKq9mTz2Rb`）。可通过网址 `#种子` 分享。

**命名随机流**：`rng.fork("worldgraph")`、`rng.fork("L37.water")`……每个阶段独立。改动一个阶段不会连带改变其他阶段的输出，利于调试与回归。

**确定性规范**：生成代码中**禁止** `Math.random`；也**不使用** `Math.sin / cos / exp / pow`。浏览器对这些函数的实现允许略有差异，会让不同设备上的同一种子长得不同。只用 IEEE-754 保证精确的加减乘除与 `sqrt`，噪声用整数哈希实现。

**世界图生成**：用图文法（Dormans 式"任务图 → 空间"）。先抽样一个依赖 DAG（能力之间的先后关系），再抽样线性扩展，允许多条合法顺序。插入 ≥ 2 个环路作为捷径。

### 9.3 各层专用生成器

| 层 | 算法 | 关键点 |
|---|---|---|
| L0 | **漂移式 WFC**：基于波函数坍缩的房间瓦片组合，附带"漂移参数" d | d 随离出生点距离增大，壁纸图案、灯光色温、门高度逐渐偏离——"重复但不对" |
| L1 | 营地模板拼装 | 居民属性（诚实度、需求、秘密）程序化 |
| L2 | 管网流量图 + 阀门谜题 | 先放蒸汽流，再放阀门，使得每道谜题至少一种解 |
| L37 | 房间网格 + 水位场 + 拱门连接 | 水位关联阀门；排水后开启新通路 |
| LX | 力导向布局 + 标注语法 | 箭头、圆圈、文字标签是真实的游戏对象 |
| LΩ | 非欧房间图（传送门图） | 连接关系不能嵌入平面；循环走廊遵循每盘不同的规则 |

### 9.4 验证（炫技点 S2）

1. **单调闭包求解**：能力只增不减，所以不必搜索 `(位置 × 能力集 × 开关)` 的巨大状态空间。反复"算出当前可达区域 → 收集区域内能力 → 重算"，直到不动点。复杂度近似 O(迭代次数 × 房间数)。
2. **物理一致的可达性**：边的通行条件用真实移动常量预计算的跳跃弧表来判定，并加 15% 保守余量。
3. **软锁检查**：对每个可达状态做反向可达性，确认总能回到枢纽或逃生接缝。
4. **时长估计**：由路径长度、预期战斗时间估计，不在 60–120 分钟范围内则重抽。
5. **重抽机制**：失败时递增种子后缀重新生成，保持确定性。
6. **运行时限制**：死亡坠落的落点由同一个求解器限制，只选"当前能力下已可达"的区域，不会出现意外跳关。
7. **Bot 抽样验证**：Node 里用真实角色控制器跑 A* 机器人通关，抽查模型与实际手感是否一致（见第 18 节）。

### 9.5 性能预算

| 项目 | 预算 |
|---|---|
| 单层生成 | ≤ 2 s（中端笔记本），运行在 Worker 内 |
| 开局生成 | 世界图 + L0 + L1，其余层在空闲时后台生成 |
| 加载界面 | 真实进度条 + "Buffering…" 圆圈，直接作为界面的一部分 |

## 10. 死亡与坠落

对应 Q12c。

- **生命归零 = 磁带弹出（Eject）**：定格，播放"磁带弹出"动画，随后坠入另一个层级。
- **落点**：从"当前能力下可达"的层级里加权抽取，优先选择最近没死过的；落点用预先生成的"落脚点"。
- **惩罚**：背包里的非绑定物品留在**尸体录像带**里；理智重置为 60；能力、已解读知识、NPC 信任度均保留。
- **回收**：触碰尸体录像带，取回物品。
- **重播（Rerun）**：如果同一层死过，尸体录像带会生成你上一次最后 10 秒的**幽灵回放**（位置轨迹以 10 Hz 记录，另含攻击事件）。幽灵会按轨迹移动并攻击你，你需要躲开或暂停它再取回物品。幽灵不重新模拟，只回放轨迹，所以鲁棒。
- **理智归零**：信号丢失，没有尸体，随机落点，地图记忆被打乱 2 分钟。

### 10.1 死亡即上传（炫技点 S9）

每次死亡自动生成一条"视频"：

- 标题模板：`【4K】深夜独自探索{层级名} {时长} 没想到{事件}`
- 缩略图：把死亡瞬间的画面缩小存下。
- 播放量、点赞数：由本次表现生成。
- 弹幕与评论：从**本次运行的事件日志**里用模板生成自然语言，例如事件日志里记录了"在第 3 分 12 秒无视了笔记里的规则"，评论就会是"其实他一开始就看到了，只是没当回事"。
- 部分评论是真实线索，部分是迷惑；理智低时的评论更不可靠。

这是纯模板 + 事件日志驱动的生成，成本低，但能让每一次死亡都变成一条属于你自己的内容。

## 12. 叙事

对应 Q14a、Q15c。

### 12.1 载体

| 载体 | 数量预算 | 说明 |
|---|---|---|
| 文档 | 约 60 | SCP 风格档案，带 ██ 涂黑与编辑痕迹 |
| 录像带 | 约 12 | 游戏自己的渲染器按关键帧脚本播放的短片 |
| 涂鸦 | 约 40 | 墙上文字，理智低时会变形 |
| 弹幕与评论 | 约 50 条手写模板 + 生成 | 世界的"旁白"，也可能说谎 |

约 160 个碎片：约 40 个手写主线碎片，约 120 个模板化碎片。每个碎片带有 `type`、`truthfulness`（真 / 假 / 存疑）、`clueTags`、`prerequisites`。

### 12.2 线索墙（Return of the Obra Dinn 式推理，轻量版）

- 一块软木板，节点是**假说**（"我已经死了"、"这里是缓存"、"它们想被看见"），边是支持它的线索。
- **三线索原则**：任何重要结论至少有 3 条独立线索，避免卡关。
- 解读完整会获得被动奖励：对应实体的理智伤害下降、对应规则标为"已证实"。**知识即力量**，也让战斗与叙事互相强化。

### 12.3 设计者真相（不直接告诉玩家）

后室在这里是"尚未缓冲完的区域"：所有场景都是被观看后又被抛弃的视频留下的缓存。实体是"想被看见"的残缺画面，所以它们的规则几乎都与**被观察**有关。玩家是"观众"，而第四面墙之外的真正玩家，也是观众。理智很低时，界面会问"你还在看吗？"，但不会以惊吓的方式出现。

三种读法同时成立：A. 你已经死了，困在缓冲里；B. 你正被看着；C. 后室就是评论区。

### 12.4 无结局：自动播放与推荐算法（炫技点 S10）

- LΩ 的进度条不可击败，只能按下"下一个"。
- 下一盘录像带由**推荐算法**生成：记录玩家行为向量（战斗倾向、潜行倾向、探索度、冒险度、与各势力关系），用它调整下一盘的生成参数（实体密度、规则变异程度、层级主题权重）。
- 界面文案是："因为你……，你可能还想看：……"。
- 世界没有终点，但每一盘都有完整的弧线，且下一盘会"认识你"。

## 13. 视听规格

### 13.1 渲染管线（炫技点 S1）

**为什么这样做**：低分辨率像素画 + 高质量后处理，是最能出效果、又不依赖美术资源的组合。

```
Canvas2D 低分辨率场景（384×216）
  ├─ 光照：低分辨率光照贴图 + multiply 合成
  └─ 上传为 WebGL2 纹理
        ① Bloom（降采样模糊链）——梦核
        ② NTSC 复合信号模拟——亮度/色度分离，色度横向拖尾，轻微点爬行
        ③ 磁带瑕疵——逐行抖动（wow）、跟踪误差横带、底部磁头切换噪点、掉线白条
        ④ 理智扭曲——桶形/波纹形变、色差、双影（时间反馈）、色阶海报化
        ⑤ 像素网格 / 扫描线（可选）
        ⑥ 暗角 + 胶片颗粒
  最后在原生分辨率叠加：OSD（REC ● 03:14:07 / PLAY ▶）与矢量标注（怪核）
```

- 池核专用：**焦散着色器**（可动画的泰森多边形或多层波叠加），叠在被水照亮的墙面。
- 怪核专用：标注用**矢量笔触**画在原生分辨率上，与模糊的磁带形成对比。
- 所有参数由层级 + 理智驱动。
- 回退：不支持 WebGL2 时，降级为 Canvas2D（CSS 滤镜 + 简单扫描线）。
- 预算：GPU 后处理总耗时 ≤ 2 ms @ 1080p 集成显卡。

### 13.2 美术资源（零外部文件）

- **精灵 DSL**：用字符矩阵 + 调色板描述像素画，运行时生成精灵表，并可按层级重着色、抖动。
- **程序化纹理**：壁纸、地毯、瓷砖、锈迹用噪声与细胞自动机生成，再量化到调色板。
- **角色动画**：关键帧精灵 + 程序化补间（呼吸、摆动、受击挤压）。
- 目标：约 40 帧玩家、约 150 帧实体、约 60 种瓦片，全部写在代码里。

### 13.3 音频（全程序合成）

**总线结构**：源 → 层级总线（程序化脉冲响应混响，每层衰减不同）→ 遮挡低通 → 主总线（压缩器 + 限幅器）。

| 层 | 内容 |
|---|---|
| 荧光灯嗡鸣 | 100/120 Hz 基音 + 谐波拍频，幅度与灯光闪烁状态联动 |
| 房间底噪 | 滤波噪声，按房间体积调整 |
| 磁带 | 嘶声、由调制延迟线实现的 wow / flutter 音高抖动 |
| 生成式音乐 | L0 走音八音盒（残缺的马尔可夫旋律）；L37 长混响铺底 + 滴水；LX 数字广播（共振峰"语音"读数字与坐标）；L1 超市背景乐；LΩ 慢放摇篮曲，受快进/倒带状态影响 |
| 空间化 | `StereoPannerNode` 等功率声像 + 距离低通；实体有声音签名，规则通过声音暗示（例如雕塑靠近时环境变安静） |
| 理智映射 | 音高漂移（音分）、低通截止、反向片段 |
| 音效 | 脚步（按材质）、门、水（滤波噪声）、磁带点击、倒带啸叫，全部合成 |

- 进阶（可选）：用 AudioWorklet 实现 wow/flutter 与 bitcrusher，通过 Blob URL 内联，不增加外部文件。
- 响度遵循宪章第 4 条。

### 15.2 关键技术决策

| 决策 | 内容 | 理由 |
|---|---|---|
| 固定步长 | 60 Hz 模拟 + 渲染插值，支持时间缩放 | 确定性是倒带、回放、测试的基础 |
| 确定性 | 模拟内 RNG 状态纳入快照，禁用 `Math.random` | 倒带后行为必须一致 |
| 快照环 | 预分配 `Float32Array`，每帧一份，保留 240 帧（4 秒）；估算 ≤ 256 实体 × 16 浮点 × 4 B ≈ 16 KB/帧，总计 ≈ 4 MB | 倒带的成本可控 |
| 生成在 Worker | 通过 Blob URL 内联 Worker | 单文件交付、不卡主线程 |
| 空间结构 | 空间哈希做宽相；热点数据用结构数组 | 控制每帧开销 |
| 存档 | localStorage + IndexedDB，带版本号与迁移，可导出 / 导入文本 | 长期可维护 |
| 构建 | 自写最小打包脚本，只用 Node 内置模块，输出单个 HTML；必要时退回 esbuild（仅开发期） | 保持运行时零依赖 |
| 体积目标 | 压缩后 ≤ 1.5 MB（无外部资源） | 方便分享 |

### 15.3 遥控器的实现要点（炫技点 S3）

- **暂停**：给范围内实体打"时间缩放 = 0"标记，粒子与计时器同步冻结。
- **倒带**：从快照环反向弹出，2× 速播放，同时开启 VHS 倒带视觉（横向撕裂、色彩饱和、拖影）。
- **快进**：玩家冲刺是时间缩放 ×2.2 的局部区域；物体老化是把它的"年龄"状态机按步长快速推进。
- 难点是"哪些状态进快照"。规则：凡是影响后续模拟的动态状态都进，音频与纯视觉粒子不进。

## 18. 测试与质量

| 类别 | 内容 |
|---|---|
| 确定性测试 | 同一种子在 Node 里生成两次，`LevelData` 必须字节一致；同一输入序列下模拟结果一致 |

## 20. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 范围过大 | 做不完 | P0/P1/P2 分级与裁剪线；先做垂直切片 |
