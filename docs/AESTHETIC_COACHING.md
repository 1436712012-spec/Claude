# 《梦隙 NOCLIP BLOOM》审美校准指令

> 用途：直接交给负责开发本项目的 AI Agent，作为审美与视觉验收的硬性标准。
> 来源：本仓库 M0 原型在实际运行、截图和像素检查中踩过并修复的问题（截图见 `docs/screenshots/`）。

---

## 0. 先学会看：没有截图就不算完成

你最大的问题通常不是不会写，而是**写完之后没有认真看**。从现在起，每完成一处视觉改动，必须完成以下三步：

1. **截图**：运行游戏，截三张图——标题、战斗中期（同屏 200 个以上敌人）、升级界面。
2. **回答五个问题**，每个问题用一句话写下答案：
   - 第一眼看到的是什么？它是否应该是玩家？
   - 画面里最亮的地方在哪？它值不值得这么亮？
   - 画面里最脏、最灰的地方在哪？
   - 有没有一种颜色不属于这个世界？
   - 遮住 HUD 之后，这张图能不能当作宣传图？
3. **像素抽查**：在截图上取地面、阴影、主角三处的颜色值，对照第 3 节的目标区间。

凡是没有截图依据的"已经很好看了"，一律视为未完成。

## 1. 梦核不是一层滤镜

梦核的核心是：**熟悉的地方，空无一人，光线太温柔，有一点不对劲**。

它不是下面这些东西：

- 粉紫或蓝紫的霓虹渐变；
- 满屏辉光和常驻的 VHS 噪点；
- 黑底红字的恐怖风；
- 大面积的毛玻璃卡片。

恐惧来自"空"和"不对劲"，比如一个笑得太宽的气球，或者一个没有脸的同学，而不是来自暗和血。

## 2. 色彩：克制是最高级的饱和

本作 L0 泳池层的基准色板：

| 角色 | 颜色 | 规则 |
|---|---|---|
| 瓷砖地面 | `#ECEFEC` – `#F4F2EC` | 白，但不能是纯 `#FFFFFF`，也不能发灰 |
| 勾缝 | `#A8B5BA` 一带 | 必须看得见，瓷砖感靠它撑起来 |
| 浅水 | `#6BD6DB` 一带 | 全画面饱和度最高的大色块，只给水 |
| 深水 | `#1A7597` 一带 | 用来表现池心深度 |
| 墙顶压顶 | `#B3D9E0` 一带 | 必须和地面拉开色相，否则墙会消失 |
| 阴影 | 偏冷的蓝灰 | **绝不使用纯黑或中性灰阴影** |
| 红 | 只用于受伤和危险 | 全作只有这一处 |

配比遵循 60/30/10：60% 白瓷，30% 水蓝与冷阴影，10% 粉彩点缀（气球、音符、拍立得）。

点缀色单块面积要小。点缀砖出现概率控制在约 1% 以下；颜色要淡，不能抢戏。

## 3. 光与色调映射：浅色世界最容易翻车

浅色画面只有两种死法：**发灰**和**过曝成一片**。M0 两种都犯过。

| 错误 | 原因 | 修法 |
|---|---|---|
| 整体发灰、粉彩变脏 | AgX/ACES 会压低高光饱和度 | 粉彩项目改用 `THREE.NeutralToneMapping` |
| 地面一片白，看不见瓷砖 | 半球光、主光、环境光三者叠加过量 | 降低补光，地面亮度目标见下 |
| 全屏糊成奶油色 | 泛光阈值低于地面亮度 | 泛光阈值要高于"被照亮的白墙"，只让真正的光源发光 |
| 地面和墙一样白 | 只调了亮度，没有色相差 | 墙顶换成浅水蓝，地面保持暖白 |
| 勾缝上出现一条条白亮线 | 用屏幕导数从陡峭高度场求法线 | 勾缝只用颜色和粗糙度表达，不扰动法线 |

数值目标：

- 色调映射之后，地面亮度落在 **0.78 – 0.90**，绝不能被截断到 1.0。
- 主光与补光之比约为 **3:1**，阴影才有体积。
- 主光和半球光用中性偏冷的白；暖色只来自小夜灯这类叙事光源。

## 4. 可读性高于氛围

割草游戏的第一审美是：**满屏 800 个东西时，一眼找到自己**。

- **主角是全画面对比度最高的物体**：加一圈半透明墨色描边（反向外壳），配色避开地面色。
- **白色的物体放在白色地面上，必须加线**：纸人原本白对白不可读，加了墨线外壳之后才成立。
- **敌人靠剪影区分，不靠颜色**：大头气球、立领制服、平面纸人，缩到 30 像素高仍要认得出来。
- **特效亮度有预算**：武器光环不准盖过主角。M0 的小夜灯第一版是一团橙色火球，把主角洗白了；最终只留一道细光环加很淡的地面光晕。
- **伤害数字**：普通伤害小而淡，暴击才用强调色。

## 5. 空间与镜头

- 俯角约 55° 时，墙高约 1.8 米合适。墙太高会把顶面连成一大片空白，也挡视线。
- 墙挡住玩家时，在屏幕空间开一个**圆形窥孔**做抖动溶解。按墙块的世界坐标去切，会切出锯齿台阶。
- 移轴景深只模糊画面上下边缘，焦平面跟随主角。它的作用是让世界像一个被凝视的微缩模型，而不是让整张图变糊。
- 雾按"离主角的水平距离"计算，形成梦境能见泡，敌人从雾里浮现。不要按相机距离算，那样主角自己也会被雾罩住。

## 6. UI：长在世界观里，而不是套模板

- **禁止**：通用后台风卡片、霓虹描边按钮、emoji 当图标、所有东西都居中且一样大的圆角、到处滥用毛玻璃。
- **升级界面**用拱形门加拍立得，这是阈限空间自己的语言。门的背面不应该还看得见拍立得（给拍立得加 `backface-visibility: hidden`）。
- **字体分工**：
  - 标题用宋体衬线（Noto Serif SC）；
  - 正文与数字用圆润的无衬线体（Nunito）；
  - 伤害数字与拍立得标签用手写体（Caveat；中文回退到 Long Cang）。
  - 每一种字体都必须有真实可用的回退，并检查中文是否会落到系统黑体上。
- **动效**：用弹簧曲线（CSS `linear()` 采样），要有回弹和重量。没有目的的动画一律删掉。
- **文字排版**：中文短句避免最后一行只剩一个字，使用 `text-wrap: balance`。

## 7. AI 审美病自查清单

逐条检查，出现任何一条都要修：

- [ ] 使用了 three.js 默认材质的灰色，没有任何材质设计
- [ ] 阴影是纯黑或中性灰
- [ ] 主角在截图里不是第一眼看到的东西
- [ ] 存在白对白、浅对浅、没有描边的可交互物体
- [ ] 泛光让大面积区域发光
- [ ] 常驻 VHS、色差、扫描线等廉价特效
- [ ] 紫蓝或粉紫渐变背景
- [ ] emoji 充当图标
- [ ] 中文被渲染成系统默认黑体
- [ ] UI 是通用模板，换个游戏也能直接用
- [ ] 声称"已优化""很精致"，却拿不出截图

## 8. 工作方式

每一轮都按这个循环走：**改一处 → 截图 → 回答第 0 节的五个问题 → 像素抽查 → 记录差距 → 修最影响整体的那一处 → 再截图**。

一次只改一个变量，否则你不知道是哪一处改动让画面变好或变坏。

把每一轮的截图路径、发现的问题和修法记进 `TASK_STATE.md`。
